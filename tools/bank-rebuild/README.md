# Rebuilding `mpsc-state-tax-officer` from source

`src/data/banks/mpsc-state-tax-officer.ts` is **generated**. Do not hand-edit it —
edit the inputs here and re-run the pipeline.

## Why this exists

The original bank was built by OCR-ing scanned exam PDFs. The extractor
mis-split multi-column pages: one option field would swallow the next several
questions whole, and because question ids were re-indexed `q001…qN` per paper,
the swallowed questions vanished with no numbering gap to reveal it.

Measured damage against the real papers:

| Sitting | Real Qs | Was in bank | Lost | Status |
|---|---|---|---|---|
| Inspector of Taxes, Jan-2016 | 400 | 309 | 91 | rebuilt |
| Excise & Narcotics, Nov-2019 | 400 | 321 | 79 | rebuilt |
| Excise & Narcotics, Feb-2021 | 400 | 301 | 99 | rebuilt |
| Group B Combined, Jul-2024 | 150 + 26 | 141 | 35 | rebuilt |
| Excise & Narcotics, Aug-2025 | 186 | 189 | mis-split | rebuilt |

**The root cause:** 14 of the 15 older PDFs already had a perfectly good text
layer. The pipeline OCR'd them anyway, and the OCR mis-ordered multi-column
pages. Only Jan-2016 GS-III is a genuine scan.

All five sittings are now rebuilt. The English **Paper-I** papers (2016, 2019,
2021) are descriptive — précis, letter, comprehension — and are not MCQ sets;
they are left as they were.

## Ground truth

Source PDFs live under
`~/Downloads/mpsc_pdfs_examination/Old_Questions/`. Two different kinds:

* **Aug-2025 papers** are digital PDFs with a real text layer — parsed exactly
  by `parse2025.py`, no OCR and no model involved.
* **Jul-2024 papers** are scans with no text layer — transcribed by reading the
  page images. Results are checked in as `parsed-2024-*.json` so the transcription
  is not repeated on every run.

Answers come from the **published MPSC final answer keys**, transcribed into
`official-answer-keys.json` (see that file for the notification numbers). Those
questions carry `answerSource: 'official'`. Everything else is
`answerSource: 'derived'` and is badged as inferred in the UI.

No official key has been published for 2016 / 2019 / 2021, nor for the 2024
General English paper — those 26 questions were solved and are marked derived.

## Running it

Two phases. Phase A rebuilt the key-backed sittings (2024, 2025); phase B the
rest (2016, 2019, 2021). Each ends in `apply.py`, which regenerates the `.ts`.

```sh
cd tools/bank-rebuild
node dump-bank.mjs            # current bank -> bank.json (input to both merges)

# --- phase A: the sittings with an official answer key ---
python3 parse2025.py          # 2025 papers from their text layer -> parsed-2025.json
python3 merge.py              # -> bank-rebuilt.json, merge-report.json
python3 apply.py              # -> src/data/banks/mpsc-state-tax-officer.ts

# --- phase B: 2016 / 2019 / 2021 (no official key) ---
node dump-bank.mjs            # re-dump, so phase B builds on phase A's output
python3 parse_native.py       # 11 papers from their text layer -> parsed-native.json
python3 validate.py parsed    # option ORDER + hygiene, checked against the PDFs
python3 merge_native.py       # -> bank-rebuilt.json
python3 retag_history.py      # splits the flat gs1_history bucket into
                               # gs1_history_ancient/medieval/modern/art_culture
                               # (by a per-id lookup, not a heuristic) --
                               # run this once, after merge_native.py and
                               # before apply.py, any time bank-rebuilt.json
                               # has just been regenerated
#   ... solve/ *.json are then answered by hand/agent into *.solved.json ...
python3 apply.py              # folds in solve/*.solved.json -> the .ts

cd ../.. && npx tsc --noEmit  # always typecheck after
```

Re-running a phase on an already-rebuilt bank is a no-op — it reproduces the
same file byte for byte.

`validate.py bank` re-checks the emitted bank (needs a fresh `dump-bank.mjs`).

`bank.json`, `bank-rebuilt.json`, `parsed-2025.json`, `parsed-native.json` and
`merge-report.json` are gitignored: they are regenerated by the steps above. The
checked-in inputs are the ones that cannot be re-derived by script — the
vision-transcribed `parsed-2024-*.json` and `parsed-2016-GS-III.json`, the
`underlines.json` markup, `official-answer-keys.json`, and the answered
`solve/*.solved.json` / `solved-2024-English.json` / `explained.json`.

## Why option ORDER is the thing to guard

Everything is positional: the answer keys say "(B)", the UI prints (a)-(d) by
index, and `answerIndex` is an integer. A silently reordered option set turns a
correct answer into a wrong one with no visible symptom.

Two defences, both of which must stay:

* `validate.py parsed` re-reads each source PDF and confirms every question's
  options appear **in the paper in the order they are stored**, anchored on that
  question's own stem. Currently 1,092 of 1,100 verified, 0 mismatches (the
  other 8 are figure-based and have no text options).
* `merge_native.py` never carries an old `answerIndex` across positionally. It
  looks up the TEXT of the option the old answer pointed at and finds that text
  among the newly extracted options. No unambiguous match ⇒ the answer is
  dropped and the question goes to `solve/` to be answered afresh. This is why
  129 old answers were discarded rather than trusted.

`merge-report.json` is worth reading after step 2: it lists every question where
the old bank's answer **disagreed with the official key**. That pass found 32 —
questions the app was actively teaching wrong (e.g. Mizoram's state animal was
marked *Sakei* / tiger; the official answer is *Saza* / serow).

## Things that will bite you

* `apply.py` enforces invariants (4 options, in-range `answerIndex`, no blank
  options, non-empty explanation) and **refuses to write** if the rebuilt papers
  fail. Pre-existing breakage in the not-yet-rebuilt papers is counted and
  reported, not treated as fatal — otherwise this could never land.
* The emitted `.ts` splits questions into chunked arrays. One 1,300-element
  `BankQuestion[]` literal trips `TS2590: union type too complex to represent`.
  Don't "tidy" it back into a single array.
* Figure-based questions (non-verbal reasoning whose options are diagrams) carry
  `figureBased: true` and an empty `options` array. They are browsable but
  excluded from scored mock tests. Do not backfill placeholder options.
* One 2024 GS-III question is `compensated: true` with `answerIndex: -1` — MPSC
  withdrew it and gave the mark to everyone. It has no correct answer by design.
