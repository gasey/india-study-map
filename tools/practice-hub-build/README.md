# MPSC Practice Hub 2 — build pipeline

Serves `/mpsc-practice-hub-2/index.html`. Browse past papers, drill a filtered
subset, sit timed mocks with the real mark scheme, and re-attempt only what you
got wrong.

**Built 2026-09-07** from four MPSC papers: JAO July 2026 Paper I & II, Circle
Officer April 2026 Paper I & II. 327 MCQs + 14 written items.

---

## Adding a paper (the whole point of this pipeline)

Nothing about any specific paper lives in `app.js`. Exams, papers, section
headings, topic filters and mark schemes are all read from the generated
bundle. So adding a paper is four steps and no app code:

1. Write `staged/<paperId>.json` (schema below).
2. Add the expected counts to `expected.json`.
3. `python3 tools/practice-hub-build/validate.py`
4. `python3 tools/practice-hub-build/build.py`

The app picks it up on reload. If you catch yourself about to type a `paperId`
into `app.js`, the data model is missing something — fix the data model.

The app also loads the daily Current Affairs archive at runtime from
`public/data/current-affairs/index.json` and its dated JSON files. Those records
are adapted into the same paper/question shape in `public/mpsc-practice-hub-2/app.js`
so they participate in Browse, Practice, Mock Test, Review and Progress without
being copied into this generated bundle. New current-affairs dates therefore
appear in Hub 2 after deployment without rebuilding `papers.js`.

### Files

| File | Role |
|---|---|
| `staged/*.json` | One per paper. Generated by `stage.py` from the inputs below. |
| `expected.json` | Per-paper question counts. A hard assertion, not a hint. |
| `taxonomy.py` | Topic slug → subject group + display label. |
| `validate.py` | Fidelity gate. Run before every build. |
| `build.py` | Emits `public/mpsc-practice-hub-2/data/papers.js`. |
| `extract.py` | PDF → questions + the highlighted option. See below. |
| `stage.py` | Extractor output + authored inputs → `staged/*.json`. |
| `merge_answers.py` | Verification output → `answers/<paperId>.json`. |
| `visual-fixes.json` | Questions the text layer cannot represent, read off renders. |
| `conventional-sections.json` | Essays/précis/letters/comprehension + guidance. |
| `answers/*.json` | Verified `answer`/`conf`/`why`/`topic`/`flag` per question. |

`data/papers.js` is **generated** — editing it directly means the next build
silently reverts you. Since 2026-09-15 `staged/*.json` is generated too: author
`visual-fixes.json`, `conventional-sections.json` and `answers/*.json` instead,
and re-run `stage.py`. A paper predating that pipeline can still be hand-authored
in `staged/` — `stage.py` only writes the paperIds listed in its `PAPERS` table.

## Extracting a new booklet

```
python3 tools/practice-hub-build/extract.py <pdf> <blue|pink> out.json
python3 tools/practice-hub-build/stage.py <dir-holding-out.json>
```

Then verify the answers, `merge_answers.py` them, re-run `stage.py`, and build.

**The highlight is invisible to text tools.** It is a filled rectangle in the
content stream: `pdftotext` cannot see it and pdfminer reports every path as
black. So `extract.py` rasterises each page and, for every `(a)`–`(d)` marker the
text layer gives, measures what fraction of that marker's pixels carry the
highlight colour. Do not "improve" this by clustering highlight pixels into boxes
and reading the text underneath — that was tried, and padding loose enough to
rejoin an antialiased fragment also merges two adjacent options, so it miscounts
in both directions at once and silently.

The cut between marked and unmarked is chosen to maximise the number of questions
with **exactly one** marked option, because that is the structure every MCQ has.
Do not switch it to "split at the widest gap": highlights vary in how tightly
they are drawn, and on SI Paper II that heuristic discarded a real mark.

**Read the run's report.** `extract.py` names what it could not do — `UNMARKED`,
`MULTI-MARKED`, `LAYOUT` (fractions or image-only options needing a render),
`bleed`, numbering jumps, conventional items held back. Every one of these has
been a real defect at least once. An `UNMARKED` question is sometimes genuine
(LESO Paper I Q15 has no highlight in the source) and sometimes a faint one the
threshold dropped — check a render before believing either.

**Things the extractor now handles, each of which shipped a silent bug first:**
Symbol-font maths in the private use area; super/subscripts, which arrive as
their own line and once turned `x² − kx − 3 = 0` into an unanswerable
`x−kx−3=0`; ordinal suffixes; the rupee sign, drawn as vector art; running
footers and the end-of-paper `* * * * * * *`; `Direction` ranges, which otherwise
attach to every later question; in-text option references like
`Both (a) and (b) are correct`; conventional sections, whose written sub-parts
`(a)`–`(e)` look exactly like MCQ options; and **underlines**, which for a
parts-of-speech item *are* the question.

## Paper schema

```jsonc
{
  "paperId": "jao-2026-p1",          // must equal the filename stem
  "exam": "Junior Accounts Officer (JAO)",
  "examShort": "JAO",                // used in compact UI labels
  "dept": "Food, Civil Supplies & Consumer Affairs Department, Govt. of Mizoram",
  "sitting": "July 2026",
  "year": 2026,                      // sorts newest-first
  "paper": "Paper I",
  "paperTitle": "General English",
  "series": "A",
  "maxMarks": 100,
  "durationMin": 180,
  "negativeMark": 0.33,              // fraction of markPerQuestion lost per wrong answer
  "markPerQuestion": 1,              // SET THIS — see below
  "sourcePdf": "jr-accounts-officer-paper-i-general-english-series-a.pdf",
  "questions": [ /* … */ ],
  "descriptive": [ /* … */ ]
}
```

`markPerQuestion` drives the mock score. If you omit it, `build.py` guesses
(2 marks when `maxMarks >= 200`, else 1) and **prints what it guessed** — it
will not default in silence. Confirm against the booklet and set it.

### `questions[]`

```jsonc
{
  "id": "B11",                       // unique within the paper
  "n": 11,                           // printed number; sub-parts may share one
  "part": "B",                       // "A" / "B"; gaps in `n` per part are an error
  "direction": "Identify the part of speech of the underlined words",
  "passageRef": null,                // id of a descriptive passage entry, or null
  "q": "The **children** played happily.",
  "opts": { "a": "Pronoun", "b": "Noun", "c": "Verb", "d": "Adverb" },
  "figure": "…",                     // optional: prose description of an image-only figure
  "marked": "b",                     // the highlight in the source PDF, or null
  "answer": "b",                     // the solved answer
  "conf": "high",                    // high | medium | low — honest, never inflated
  "why": "…",                        // the teaching text; shown on reveal
  "topic": "parts_of_speech",        // see taxonomy.py
  "flag": null                       // or a string naming a real defect
}
```

- `**word**` marks the word underlined in the source. For a parts-of-speech
  item the underline *is* the question, so it has to survive to the screen.
- `\n` is honoured in `q` — keep numbered statement lists intact rather than
  summarising them away.
- A topic slug missing from `taxonomy.py` still builds (it lands under "Other")
  but `validate.py` names it so you can decide whether to add it properly.

### `descriptive[]`

Essays, précis, letters, comprehension written answers, and the reading
passages they attach to. `kind` is one of `essay`, `precis`, `letter`,
`comprehension_written`, `passage`. `guidance` carries model-answer advice —
these items can't be drilled as MCQs, so the guidance is the only thing
carrying them.

## `marked` is not an answer key

Every one of these PDFs has options highlighted, and it is tempting to treat
them as an official key. **They are not.** MPSC has published no key for these
sittings. The highlights are someone's marked answers and they contain
outright errors — JAO Paper I alone has three, including Q6 "Which part of
speech describes a noun?" highlighted as *Verb*.

So `marked` and `answer` are separate fields on purpose. Where they differ the
app says so on the question, shows both, and gives the reasoning, rather than
quietly picking a winner. Preserving the disagreement is the feature.

By the same logic every answer renders as `derived · high|medium|low` and never
as authoritative — an unrated answer must not be able to read as an official
one by omission. (This is the same trap recorded in `CLAUDE.md` for the
`provLine()` helper that badged 309 derived answers as official.)

## Why `expected.json` is a hard gate

This repo has already lost ~280 questions to an extractor that dropped them
with no numbering gap to reveal it (DEVLOG 2026-08-04). The lesson taken was
not "be more careful" but "make the count something a build cannot pass without
satisfying". `validate.py` fails the build on a count mismatch and on any gap
in per-part numbering. A repeated `n` is only a note — a paper may legitimately
print sub-parts like Q4(e) and Q4(f) that share one number.

## Progress storage

`localStorage` under `ph2:v1` — its own namespace, deliberately. Attempts are
keyed `<paperId>:<questionId>`, which is what makes "not attempted" and "wrong
last time" work across papers and survive a rebuild. Export/import lives behind
the ⛁ button in the app.
